# sandwor.ru — правила для разработки

Сайт собран на дизайн-системе sandwor. **Любой новый экран, секция или компонент
строится только на ней** — своих цветов, шрифтов, кнопок и карточек «по месту» не
делаем. Справка по компонентам — `src/shared/sandwor/README.md` и типы с описаниями
пропсов в `src/shared/sandwor/types/index.d.ts`.

## Где что

| Что                                          | Где                                                                                     |
| -------------------------------------------- | --------------------------------------------------------------------------------------- |
| Дизайн-система (копия архива)                | `src/shared/sandwor/` — токены, шрифты, `src/components/*.jsx`, `types/`                |
| Локальные правки ДС                          | `src/shared/sandwor/CHANGES.md`                                                         |
| Разметочные примитивы сайта                  | `src/shared/ui/` — `PageHero`, `Section`, `SectionIntro`, `StatusScreen`, `Link`        |
| Секции, которые повторяются между страницами | `src/widgets/` — `ServicesGrid`, `ProcessSection`, `PriceCalculator`, `FaqSection`, …   |
| Бриф (единственная форма заявки)             | `src/features/brief` — `BriefButton`, `useBrief().openBrief({ services })`, `BriefCard` |
| Направления, цены, сроки                     | `src/entities/service/model/services.ts`                                                |
| Тексты                                       | `messages/ru.json`, `messages/en.json` — всегда обе локали                              |

## Как собирать новый экран

1. **Каркас страницы:** `PageHero` (крошки, мета, H1, лид, действия) → секции
   `Section` с `SectionIntro` (моно-мета, заголовок heading-1, лид). Фон секций —
   `tone`: `default`, `sunken` или `canvas` (точечная сетка — единственная фактура).
2. **Содержимое — компоненты ДС**, импорт поштучно, не из barrel:
   `import { Button } from '@sw/components/Button'`. Так в бандл страницы попадает
   только то, что на ней есть.
3. **Нужного компонента нет** — сначала проверьте, нельзя ли собрать из готовых
   (Canvas, Badge, Icon, карточки). Если нет — своя композиция в `widgets/` или
   `shared/ui/` на токенах ДС, по образцу соседних (см. `FeatureGrid`, `PostCard`).
4. **Ссылки:** компоненты ДС рендерят обычный `<a href>`; `LinkInterceptor` в layout
   делает такие переходы клиентскими. Внутренние href — с префиксом локали:
   `localizeHref(path, locale)` на сервере, `useLocalePaths().href(path)` на клиенте.
5. **Заявка** — только через бриф: `<BriefButton services={['crm']}>` или
   `openBrief()`. Новых форм не заводим.
6. **Тексты** — в переводы, в обе локали. Компоненты ДС по умолчанию говорят
   по-русски: для EN передавайте `copy`, `labels`, `label`, `closeLabel` и т.п.

## Правила стилей

- Цвета, отступы, радиусы, тени, длительности — **только переменные ДС**:
  `var(--surface)`, `var(--space-6)`, `var(--radius-lg)`. Сырые HEX — нет
  (исключение: `app/api/og`, там CSS-переменные недоступны).
- Типографика — по шкале ДС: display-1 48/52, display-2 32/36, heading-1 24/29,
  heading-2 20/25, heading-3 16/21 (Unbounded 600); body 15/23, body-l 17/27
  (Golos Text); моно-метки 12/16 и цифры — Fira Code.
- Классы `sw-*` не переопределяем. Нужен новый вариант — добавляем необязательный
  проп в компонент ДС и записываем это в `CHANGES.md` (чтобы перенести в саму ДС).
- **Primary-кнопка — одна на экран**, для главного действия; остальные — secondary,
  ghost («Подробнее →»), quiet.
- Тема одна — тёмная. Светлая в ДС черновик, на сайте не включается.
- Адаптив: проверяем 375, 768 и 1280. Брейкпоинты ДС — 760 и 1100px; горизонтальной
  прокрутки на телефоне быть не должно.
- Сброс отступов (`app/reset.css`) — на `:where()` и подключается до стилей ДС; не
  добавляйте глобальных правил с обычной специфичностью для `p`, `a`, `h*` — они
  перебьют типографику ДС.

## Что сейчас скрыто и как вернуть

Сайт временно показывает только подтверждённое: разработку сайтов (лендинг на Tilda
от 50 000 ₽, магазин на Tilda от 100 000 ₽, кастом — по запросу), кейсы и статьи.
Всё остальное готово и спрятано флагами — **не удаляйте этот код**:

- `entities/service/model/services.ts` → `SERVICE_STATUS`: `active` / `soon`. У `soon`:
  карточка с плашкой «Скоро» без цены и ссылки, «· скоро» в меню и подвале, вместо
  страницы — `ServiceSoonPage` (noindex, вне sitemap), направления нет в брифе и
  палитре. Если активно одно направление, бриф начинается со второго шага.
- `shared/config/positioning.ts` → `POSITIONING`: `sites` (сейчас) или `studio`.
  Переключает тексты (`…-sites` / `…-studio` в переводах: герой, цифры, этапы, FAQ,
  мета, слоган, OG) и `FEATURES` — калькулятор и схему «Путь заявки».
- Битрикс24 не упоминаем нигде: партнёрство только с amoCRM. CRM в текстах про
  сайты — общим словом («заявки в CRM»). Тест `entities/service/__tests__` это проверяет.

## Персональные данные и документы

- Политика — `/privacy`, отдельные согласия (на заявку и на cookie) — `/consent`;
  тексты в `messages/*.json` (`privacy`, `consent`), реквизиты оператора и редакция —
  `src/shared/config/legal.ts` (метки `{operator}`, `{inn_part}`, `{email}`, `{edition}`).
- Любая форма с персональными данными — только через бриф: в нём обязательный,
  не отмеченный заранее чекбокс согласия; сервер без `consent: true` заявку не
  принимает и пишет в amoCRM номер редакции согласия.
- Новый сервис, который получает данные посетителей (пиксель, чат, CRM, шрифты или
  картинки со стороннего домена), — сначала строка в политике и согласии, новая
  `edition` (и `consentVersion`, если менялось согласие), затем код. Сторонние
  домены для картинок и шрифтов не используем — всё раздаём со своего сервера.

## Данные

- Не выдумываем цифры, отзывы и логотипы клиентов. Блоки `Stats`, `TestimonialCard`,
  `ClientLogos` выводятся, только когда есть настоящие данные (`entities/testimonial`).
- Цены и сроки — из `entities/service`, а не строками в разметке.
- Картинки к статьям — не стоковые фото, а обложки и схемы на ДС из `scripts/blog-art/`
  (у схем отдельная версия для телефона через `<picture>`).
- OG-картинки (превью при отправке ссылки) — `npm run og` после новой статьи или смены цен.

## Обновление дизайн-системы

1. Заменить `src/shared/sandwor/` новым архивом (без `preview/`).
2. Повторить или убедиться, что уже перенесены правки из `CHANGES.md`.
3. `node scripts/sandwor-dts.mjs` — пересобрать декларации компонентов.
4. `npm run lint && npx tsc --noEmit && npm test && npm run build`.

## Проверки перед коммитом

`npm run lint`, `npx tsc --noEmit`, `npm test`, `npm run build`, `npm run size`.
